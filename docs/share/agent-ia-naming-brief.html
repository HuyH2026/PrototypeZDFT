Naming recommendation

Call the section Agent Directory.

The overlap between “Manage agents” and “Agent Builder” is amplified because agent currently names two different levels of the product. Give the word one meaning: the globally selectable AI agent.

Status · Proposed Decision requested · Approve “Agent Directory” and “Use cases” as the two levels.
A
Agent Directory is the portfolio.

Create, monitor, select, and open AI agents—with or without a brand.

B
Agent Builder is the workspace.

Design the selected agent’s use cases, knowledge, actions, QA, and configuration.

The mental model

One word, one level.

Brand assignment is optional; when present, it organizes an agent. An agent is the persistent, selectable resource. A use case describes something that agent knows how to handle.

The collision

Renaming the page alone will not resolve it.

The current product uses “agent” for the portfolio rows and again for the child rows inside Use cases. The recommended change makes each level teach the next one.

Each term now has one job: portfolio resource, authoring workspace, and authored behavior.

Recommended copy

A vocabulary the interface can reuse consistently.

Short labels work because the surrounding language makes the responsibility of each surface explicit.

Model decision: the current creation flow requires a brand. Supporting agents without one means making Brand optional and introducing a distinct “No brand” group; this should be agreed alongside, but separately from, the naming change.

Ownership boundary: Agent Directory owns identity and lifecycle context—brand assignment, available channels, operational status, and default view. Agent Builder owns behavior within those channels—use cases, knowledge, actions, QA, and behavior configuration.

Selection behavior

Show the destination before the click.

Updating the global agent switcher is helpful confirmation. The confusing part would be sending visually identical rows to three different destinations without warning.

The persistent switcher updates to the selected agent and brand context.

3

Dashboard, Agent Builder, or Agent Overview—without surprise.

Alternatives considered

“Agent Directory” creates the clearest boundary.

The alternatives each emphasize only one part of a surface that spans browsing, creation, health, and lifecycle management.

01 · Recommended

Agent Directory

Makes browsing and opening the agent portfolio explicit. It is slightly longer, so the subtitle should continue to carry its monitoring and lifecycle scope.

02 · Strong alternative

Agents

Shorter and familiar, but it names the resource more than the place where users find, compare, and open those resources.

03 · Enterprise alternative

Agent Portfolio

Fits governance and aggregate health, but it is more abstract and less immediately scannable.

Recommended child term

Use case

“Use case” is broad enough to cover Service cancellation, Knowledge Retrieval, and Fallback while remaining business-readable.

“Intent” is too narrow for knowledge and fallback behaviors, “Capability” is more abstract, and “Workflow” implies a fixed sequence that may not exist.

Avoid · Agent Setup Avoid · Agent Administration Avoid · Agent Hub Avoid · Agent Management

“Setup” sounds temporary, “Administration” suggests permissions, “Hub” is vague, and “Management” still overlaps with the work performed in Agent Builder.

Decision boundary

Change the vocabulary, preserve the navigation model.

The recommendation clarifies where work happens without requiring a new navigation architecture or a different global-selection pattern. Optional brand membership is the one related product-model decision to resolve explicitly.

Keep

  • The global agent switcher.
  • Brands as a grouping and filtering concept.
  • Agent Builder as the selected agent’s authoring workspace.
  • Each agent’s configurable default destination.

Change

  • Rename Agent Setup and Manage agents to Agent Directory.
  • Reserve the word agent for the top-level resource.
  • Rename Agent Builder rows and actions around use cases.
  • Make Brand optional and disclose each agent’s default view.
Agent Directory identifies where users find and open agents. Agent Builder identifies where they shape one.

That distinction is short enough for navigation and strong enough to teach the product’s hierarchy as the platform grows.
